# ChatGPT/Codex Usage Status Bar 产品化设计

**日期：** 2026-08-27  
**状态：** 已获授权，作为后续实现基线  
**范围：** Windows 原生桌面工具的产品化演进

## 1. 目标与原则

项目从“能显示额度的迷你窗口”升级为“可长期维护的本地额度工具”，优先服务个人 ChatGPT/Codex 用户，同时为开发者和贡献者保留扩展边界。

核心原则：

1. **隐私优先**：OAuth 凭据只在进程内使用；本地落盘只保存设置、额度摘要和诊断所需的非敏感元数据；不建设接收凭据的服务器，不加入遥测。
2. **官方数据优先**：只展示官方接口返回的额度窗口，不根据订阅名称猜测额度，不把功能写成 Plus-only。
3. **默认可用**：首次运行即可显示；系统代理、直连和显式 HTTP/HTTPS 代理都可工作；所有可选功能都有安全默认值。
4. **可恢复**：窗口隐藏、网络失败、接口字段变化、启动项异常和更新失败都不能让用户失去重新打开或回滚的路径。
5. **可验证**：源码、构建、烟测、发布资产和诊断报告都能被用户与贡献者独立检查。

非目标：第一阶段不做云端账户系统、不上传额度历史、不代管 API Key、不静默替换用户程序、不同时支持未经验证的第三方额度接口。

## 2. 推荐技术路线

保留当前轻量 WinForms 和 Windows 自带 .NET Framework 编译能力，逐步拆分单文件源码，而不是立即迁移到 WPF、WinUI 或跨平台运行时。

原因：现有单个 EXE 约几十 KB，免安装、启动快、权限要求低，已经验证了 ChatGPT/Codex OAuth 和代理行为。直接重写会带来运行时安装、签名、迁移和回归风险；模块化拆分可以先获得可维护性，再为未来 .NET 8/WPF 版本保留迁移边界。

目录目标：

```text
src/
  Domain/          额度窗口、快照、设置和通知事件模型
  Application/     刷新调度、阈值判断、缓存协调和用例服务
  Infrastructure/  OAuth 读取、官方 Provider、JSON 存储、启动项和更新检查
  Presentation/    状态栏、设置窗口、托盘菜单和诊断视图
tests/
  Fixtures/        官方响应与异常响应样例
  Smoke/           编译、脱敏、启动项、单实例和菜单回归脚本
```

第一阶段允许这些目录暂时映射到现有文件中的内部类，但新功能不得继续无边界地堆到 `Program.Main` 或绘制方法中。

## 3. 组件与职责

### Domain

- `UsageSnapshot`：计划显示名、账户脱敏标签、窗口列表、查询状态、查询时间和稳定错误码。
- `QuotaWindow`：窗口名称、秒数、使用百分比、重置时间；百分比在模型边界内限制为 0 到 100。
- `AppSettings`：启动、自定义刷新周期、背景样式/透明度、通知开关、阈值、位置恢复和更新检查偏好。
- `DiagnosticReport`：仅由安全字段组成，禁止直接接收 OAuth Token、账户 ID、代理 URI 或原始响应。

### Application

- `RefreshScheduler`：单线程顺序刷新；默认 5 分钟，支持 1/5/10/15/30/60 分钟预设；手动刷新不会与已有请求并行。
- `NotificationEvaluator`：只在阈值从低到高穿越或窗口从未到期变为已重置时通知；同一事件有冷却时间，避免重复气泡。
- `UsageCache`：保留最近一次成功摘要，在网络暂时不可用时展示“上次成功”而非清空界面；缓存不含令牌和完整响应。
- `AppCoordinator`：协调生命周期、取消请求、设置变更、窗口刷新和托盘状态。

### Infrastructure

- `IUsageProvider`：统一 `GetUsageAsync` 契约，返回 `UsageSnapshot`；当前唯一实现为 ChatGPT/Codex OAuth Provider。
- `CodexCredentialReader`：读取 `%CODEX_HOME%\auth.json` 或 `%USERPROFILE%\.codex\auth.json`，只返回本次请求所需的内存对象。
- `SettingsStore`：在 `%LOCALAPPDATA%\ChatGPTCodexUsageStatusBar\settings.json` 保存非敏感设置；采用临时文件写入、替换和损坏回退默认值。
- `StartupManager`：实际启动命令只写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`；配置标记和其他设置写到独立配置键或 JSON，绝不把状态标记写入 Run。
- `UpdateChecker`：仅在用户手动触发或明确打开检查时访问 GitHub Releases；解析版本、下载链接和 SHA-256，提示用户后再执行替换。

### Presentation

- `StatusWindow`：保持约 320×40 的信息密度；加入 `WS_EX_TOOLWINDOW`，不出现在 `Alt+Tab`，仍可拖动、右键和点击刷新。
- `SettingsForm`：原生紧凑设置窗口，分为刷新、外观、通知、启动和更新五组；修改后即时预览，取消不写入。
- `TrayController`：提供显示/隐藏、立即刷新、设置、诊断、打开项目主页和退出；状态栏隐藏后仍有恢复入口。
- `DiagnosticsForm`：显示可复制的脱敏报告，明确提示不含凭据；错误状态提供下一步操作而非堆栈。

## 4. 用户体验决策

### 窗口与 Alt+Tab

使用 `WS_EX_TOOLWINDOW` 隐藏 Alt+Tab 和任务切换列表，保留 `ShowInTaskbar=false`。托盘图标作为唯一的可靠恢复入口。关闭按钮默认隐藏状态栏到托盘，不直接终止进程；托盘“退出”才结束程序，避免用户隐藏后无法找回。

### 刷新周期

默认 5 分钟，菜单和设置窗口提供 1、5、10、15、30、60 分钟。最小值 1 分钟，手动刷新仍受“已有请求不并行”约束。周期变更立即重启计时器，并在诊断中显示。

### 背景与透明度

提供 35%–100% 的连续不透明度滑块，默认 100%；右键菜单保留常用快捷档位：

- **100% 不透明**：当前深色背景，文字对比度最高。
- **85%/65% 不透明**：保留阴影、边框和进度条，适合叠加在桌面内容上。
- **35% 不透明**：更弱的背景存在感，仍保留可读文本和可点击区域。

设置窗口拖动滑块时实时预览，取消不会写入设置，保存后重启仍保持。

暂不提供真正的“纯透明窗口”。WinForms 的纯透明会同时影响抗锯齿、文字边缘和命中区域，实际使用中可读性和可发现性更差；后续若采用原生 layered window，会先做独立实验和可访问性验收。

### 通知

默认关闭，仅在用户打开后提醒 80%、90%、100% 阈值和重置事件。通知只使用窗口名称、百分比和本地时间，不包含账户标识、Token 或接口响应。

## 5. 数据流

```text
Timer / 手动刷新
        |
        v
RefreshScheduler --(取消旧请求/禁止并行)--> IUsageProvider
        |                                         |
        |                                  CodexCredentialReader
        |                                         |
        |                                  HTTPS usage endpoint
        v                                         v
UsageCache <---- UsageSnapshot <----------- 安全解析/稳定错误码
        |
        +--> StatusWindow / TrayController
        +--> NotificationEvaluator
        +--> HistoryStore（仅摘要）
        +--> DiagnosticsService（脱敏字段）
```

凭据流只存在于 Provider 的单次请求路径，不能进入 `UsageCache`、`HistoryStore`、日志、剪贴板或更新请求。网络层使用系统代理/直连作为默认行为，只有显式设置 `CLASH_MIXED_PROXY` 时才创建 HTTP/HTTPS 代理。

## 6. 本地存储与隐私边界

设置文件保存：刷新分钟数、背景透明度百分比及兼容档位、通知开关、阈值、窗口位置、启动偏好和最后检查版本。历史文件按设置保留 7/30/90 天（默认 30 天）或最多 500 条摘要，字段仅为窗口秒数、百分比、重置时间、查询时间、状态和应用版本。

禁止保存：`access_token`、`refresh_token`、`id_token`、`account_id`、完整 `auth.json`、代理完整 URI、原始 HTTP 响应和异常堆栈。

设置写入采用 UTF-8、临时文件和原子替换；解析失败时备份损坏文件为 `.bak` 并回退默认值，不阻止程序启动。卸载或用户选择“清理本地数据”时，只删除应用自己的 `%LOCALAPPDATA%` 子目录和启动项，不触碰 Codex CLI 凭据。

## 7. 错误与恢复

| 场景 | 用户看到的状态 | 恢复动作 |
| --- | --- | --- |
| OAuth 文件缺失/模式错误 | OAuth 不可用 | 运行 `codex login` |
| Token 过期 | OAuth 已过期 | 重新登录 |
| 代理或网络失败 | 网络不可用，保留上次成功摘要 | 检查系统代理或显式代理，点击刷新 |
| 官方 HTTP 4xx/5xx | 官方接口异常 + 状态码 | 等待接口恢复或提交脱敏诊断 |
| 响应字段变化 | 官方响应无法解析 | 提交诊断，等待适配版本 |
| 设置文件损坏 | 使用默认设置 | 修复后的文件可在诊断中看到状态 |
| 启动项无权限 | 开机自启未生效 | 右键重试或手动使用启动脚本 |
| 更新下载/校验失败 | 保持当前版本 | 手动下载 Release，绝不替换旧文件 |

所有异步 UI 入口必须有最后一道异常边界；关闭窗口时先停止调度并取消请求，再释放 Provider、托盘和窗口资源。

## 8. 发布与质量门禁

每次合并和 Release 必须：

1. 在 Windows runner 使用 `.NET Framework csc.exe` 编译所有源文件，并开启 `/warnaserror`。
2. 运行静态敏感信息扫描、`git diff --check` 和响应 fixture 解析测试。
3. 运行启动项迁移、Alt+Tab 样式、单实例、刷新周期持久化、透明度预览和诊断脱敏烟测。
4. Release 上传 `SubscriptionStatus.exe`、`SHA256SUMS.txt` 和 ASCII 元数据；远端路径不得出现问号或乱码。
5. 发布说明写清兼容性、数据边界、迁移行为和已知限制；失败构建不得标记为 Latest。

版本采用 SemVer：

- `0.x`：快速迭代，允许设置文件字段增加但必须有默认值和迁移。
- `1.0`：设置、缓存、诊断、托盘和更新检查稳定，且拥有完整回滚与测试矩阵。

## 9. 分阶段路线

### P0：可靠内核（当前优先）

- 拆分领域模型、Provider、设置存储、刷新调度和诊断服务。
- 隐藏 Alt+Tab、托盘恢复、刷新周期预设、35%–100% 背景透明度设置。
- 保留现有启动项迁移、单实例和脱敏约束。

### P1：日常使用体验

- 本地摘要历史和轻量趋势视图。
- 阈值/重置通知、设置导入导出和位置恢复。
- 中文/英文 UI 文案资源化和高 DPI 回归矩阵。

### P2：可信分发

- GitHub Release 检查、SHA-256 校验、用户确认更新和旧版本回滚。
- Release 自动生成变更摘要、校验文件和 Windows 安装/卸载辅助脚本。

### P3：生态扩展

- 在 `IUsageProvider` 边界上增加经过验证的官方额度来源。
- 多账号以显式用户操作和独立凭据引用为前提，不默认扫描或上传多个账户。
- 评估 .NET 8/WPF 或跨平台客户端，必须以不降低隐私、可移植性和安装体验为前提。

## 10. 验收标准

- 首次启动后状态栏不出现在 Alt+Tab，托盘可以显示/隐藏/退出。
- 刷新周期、背景透明度和通知设置在重启后保持，非法设置回退安全默认值。
- 无网络时界面保留最近成功摘要，并明确标记数据时间，不伪装成实时数据。
- 诊断复制内容经过字段级白名单，伪造计划声明、代理变量和错误响应不能泄露敏感文本。
- 运行两次程序只存在一个进程；关闭窗口不会留下无效启动项。
- Windows 构建、fixture 解析、启动项/单实例/脱敏烟测和 Release 校验全部通过。
- README、中文教程、SECURITY、CONTRIBUTING、CHANGELOG 与实际行为同步。
